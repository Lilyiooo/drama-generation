# 多 Agent 剧本评测 Pipeline 说明

本目录（`momomohe-multiagent`）是一个**三维度多 Agent 剧本评测系统**：输入一份剧本（txt），指定评测模型，输出「剧本逻辑 / 剧本质量 / 剧本创意」三大维度的评分、S/A/B 问题与亮点台账，以及面向下一阶段（分镜等）的优化建议。

---

## 1. 总体架构

```
输入剧本 (txt)
   │
   ▼
┌─────────────────────────────────────────────────────────────┐
│ 阶段 1：独立评审  9 次调用（每大维度 3 个评审，3 并发）        │
│   - 逻辑评审 R01/R02/R03                                     │
│   - 质量评审 R01/R02/R03                                     │
│   - 创意评审 R01/R02/R03                                     │
├─────────────────────────────────────────────────────────────┤
│ 阶段 2：台账审核  3 次调用（每大维度 1 个审核，3 并发）        │
│   - 逐条归并/纠错评审的 S/A/B 条目                           │
│   - confirmed / rejected / needs_arbitration                │
├─────────────────────────────────────────────────────────────┤
│ 阶段 3：争议仲裁  最多 3 次调用（按需触发）                   │
│   - 只裁决 needs_arbitration 的争议项                        │
├─────────────────────────────────────────────────────────────┤
│ 阶段 4：下一阶段建议  1 次调用                                │
│   - 输入：原始剧本 + 最终确认的 S/A/B 台账                    │
│   - 输出：面向分镜/台词/剪辑等制作环节的优化建议              │
└─────────────────────────────────────────────────────────────┘
   │
   ▼
结果（多份 JSON + Markdown 报告 + Web 前端展示）
```

- 核心调用量：**9 + 3 + ≤3 + 1 = 13 ~ 16 次**大模型调用。
- 各阶段之间串行衔接（评审全部完成 → 审核 → 仲裁 → 建议）；阶段内部用 `ThreadPoolExecutor` 并发。

## 3. 评分体系

### 3.1 三大维度与基线

| 维度 | 基线分 | 计分方式 |
|---|---|---|
| 剧本逻辑 logic | 90 | 扣分制（从 90 起扣问题） |
| 剧本质量 quality | 90 | 扣分制（从 90 起扣问题） |
| 剧本创意 creativity | 50 | 加分制（从 50 起加亮点） |

### 3.2 S/A/B 锚点（当前版本）

| 维度 | 类型 | S | A | B |
|---|---|---:|---:|---:|
| 逻辑 / 质量 | 问题 issue（扣分） | −10 | −6 | −4 |
| 逻辑 / 质量 | 亮点 highlight（加分） | +3 | +1 | 0 |
| 创意 | 损耗 loss（扣分） | −10 | −6 | −4 |
| 创意 | 亮点 highlight（加分） | +10 | +6 | +4 |

> 程序 `_point_anchor` 会强制把模型自报的 `points` 归一化到上述离散锚点，避免 `B/20`、`B级亮点加3分` 之类的矛盾。

### 3.3 子维度聚合（以「剧本质量」为例）

质量维度是**两层结构**：12 个子维度 → 5 个模块。

**12 个子维度**（各自从 90 起扣 SAB）：

| 模块 | 子维度 |
|---|---|
| 人物质量 | 主角 / 配角与角色功能 / 人物关系 |
| 卡点质量 | 开篇钩子 / 矛盾建立 / 一卡质量 |
| 情节规划 | 桥段质量 / 情绪节奏 / 情节结构 |
| 分集剧本 | 台词质量 / 视觉化质量 |
| 设定质量 | 设定质量 |

**5 个模块外层权重**：人物 20% / 卡点 15% / 情节规划 25% / 分集剧本 25% / 设定 15%。

**质量总分 = 加权总分 × 短板系数**，其中短板系数由最低模块分决定：

| 最低模块分 M | 短板系数 |
|---|---:|
| M ≥ 80 | 1.00 |
| 70 ≤ M < 80 | 0.97 |
| 60 ≤ M < 70 | 0.93 |
| 50 ≤ M < 60 | 0.88 |
| 40 ≤ M < 50 | 0.80 |
| M < 40 | 0.70 |

逻辑（7 个子维度）和创意（4 个子维度）则直接按各自权重加权。

### 3.4 三种分数

每个维度输出三个分数：

| 分数 | 含义 |
|---|---|
| **初始均分** initial_mean | 三个评审模型**自报总分**的算术均值（模型自己给的分，程序不校验） |
| **台账分** ledger_score | 审核/仲裁确认后的 S/A/B 台账按规则**程序重算**的最终分 |
| **融合分** fusion_score | `0.5 × 初始均分 + 0.5 × 台账分`（`FUSION_WEIGHT = 0.5`） |

前端最上方展示的是**融合分**，小字展示初始均分和台账分。

### 3.5 评级

按台账分评级：`S ≥ 90`、`A ≥ 75`、`B ≥ 60`、`C < 60`。

## 4. 运行方式

### 4.1 命令行

```bash
cd /data/workspace/drama_eval-demo/momomohe-multiagent

python evaluate_multi_agent.py <剧本.txt> \
  --model gpt-5.6-sol \
  --output-dir output/<自定义目录> \
  --review-workers 3
```

主要参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | `gpt-5.6-sol` | 评测模型 |
| `--review-workers` | 3 | 评审并发数 |
| `--audit-workers` | 3 | 审核并发数 |
| `--arbitration-workers` | 3 | 仲裁并发数 |
| `--context-mode` | auto | `auto`/`direct`/`evidence`（剧本 < 300000 字默认全文直送） |
| `--restart` | — | 清空产物重跑 |
| `--dry-run` | — | 只看预计调用量，不发请求 |

### 4.2 Web 前端

```bash
cd /data/workspace/drama_eval-demo/momomohe-multiagent
PORT=5000 python server.py      # 默认 0.0.0.0:5000，可用 PORT 改端口
```

- 本机访问 `http://127.0.0.1:5000/`，内网他人访问 `http://<机器IP>:5000/`。
- 前端功能：上传 txt 剧本 → 选模型 → 实时进度条 → 融合分大卡片 → 子维度小字 → S/A/B 明细（两级折叠）→ 下一阶段建议（按优先级折叠）。

## 7. 关键配置

- **模型密钥**：`drama_evaluator/llm.py` 从 `drama_operator-master/drama_operator_new/trpc_python.yaml` 读 Venus URL/token；可用环境变量 `VENUS_API_KEY` 覆盖（`.env` 里已配置）。
- **模型参数适配**：GPT-5.x 系列走 `max_completion_tokens`，gemini 系列走 `temperature` + `max_new_tokens`。
- **断点续跑**：`multi_agent/` 下已完成的评审/审核/仲裁产物会被复用（日志显示 `[复用]`）；剧本、模型、评分标准任一变化会触发 `--restart` 要求（基于 `manifest.json` 的 hash 比对）。

---

## 8. 已知注意点

1. **TPM 限流**：Venus 限流为 500000 tokens/min。大剧本（约 27 万字）走全文直送时，单次评审输入约 20 万+ token，3 并发会超限触发 429。建议大剧本用 `--review-workers 1` 或降低并发。
2. **逻辑维度方差大**：逻辑是"找硬伤 + S/A/B 分级 + 确认/驳回"三重主观判断叠加，对 S 级确认数极敏感，同一剧本多次评测逻辑分可能波动 10 分以上；质量/创意则稳定得多。想要稳定可多跑几次取中位数。
3. **建议阶段失败不阻断主流程**：下一阶段建议若失败会记入 errors、返回空，不影响评分结果。

---

## 9. 评分标准文件

`prompts/` 下的 `.md` 是单 Agent 版本的完整评分标准（S/A/B 定义、计分锚点、权重、边界），多 Agent 阶段会把这些标准注入评审/审核 prompt，但输出协议改为结构化 JSON。质量维度已排除「小说/指令对照质量」维度。
